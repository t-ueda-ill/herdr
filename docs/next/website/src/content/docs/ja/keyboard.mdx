Herdr はマウスネイティブです。キーバインドをひとつも覚えなくても、ペイン、タブ、ワークスペース、エージェントをクリックし、分割境界をドラッグし、右クリックメニューを使えます。キーボード操作は任意のレイヤーであり、必須ではありません。

## プレフィックスとは何か

ターミナルマルチプレクサは、ターミナルとその中で動くプログラムの間に位置します。プログラムはすでにほとんどのキーの組み合わせを使っています: `ctrl+c` は中断、`ctrl+r` は履歴検索、エディタは残りのほぼすべてを占有します。もし Herdr がよく使われるキーを直接奪えば、中のプログラムを壊してしまいます。

プレフィックスはこれを解決します。プレフィックスキー (デフォルト `ctrl+b`) を押すと、次のキー入力はターミナルではなく Herdr に送られます。`prefix+c` は「`ctrl+b` を押して離し、次に `c` を押す」という意味です。何十ものキーを予約する代わりに、ひとつだけ予約します。

いつでも `prefix+?` を押すと、すべての有効なバインドが表示されます。キーバインドヘルプで `/` を押すと、アクションとショートカットを絞り込めます。Backspace でフィルターを編集し、`ctrl+u` でクリアできます。

## まずこの 5 つを覚える

| アクション | キー |
| --- | --- |
| 新しいタブ | `prefix+c` |
| 右 / 下に分割 | `prefix+v` / `prefix+minus` |
| ペイン間の移動 | `prefix+h/j/k/l` |
| ワークスペースナビゲーション | `prefix+w` |
| すべてを動かしたままデタッチ | `prefix+q` |

これで日常の移動のほとんどをカバーできます。それ以外はマウスのままで大丈夫です。

## 残りはタスク別に

ペイン:

| アクション | キー |
| --- | --- |
| フォーカス中のペインをズーム | `prefix+z` |
| ペインを閉じる | `prefix+x` |
| ペインを入れ替える | `prefix+shift+h/j/k/l` |
| リサイズモード | `prefix+r` |
| コピーモード | `prefix+[` |

タブ:

| アクション | キー |
| --- | --- |
| 次 / 前のタブ | `prefix+n` / `prefix+p` |
| タブ 1–9 にジャンプ | `prefix+1..9` |
| タブの名前を変更 | `prefix+shift+t` |
| タブを閉じる | `prefix+shift+x` |

ワークスペースとセッション:

| アクション | キー |
| --- | --- |
| 新しいワークスペース | `prefix+shift+n` |
| ワークスペースの名前を変更 | `prefix+shift+w` |
| ワークスペースを閉じる | `prefix+shift+d` |
| Goto ピッカー | `prefix+g` |
| サイドバーの表示切り替え | `prefix+b` |

完全なキーマップとバインドの構文は[キーバインドリファレンス](/ja/docs/configuration/#キーバインド)にあります。

Goto ピッカー (`prefix+g`) は、各エージェントとターミナルをワークスペースごとに一行ずつ表示します。分割タブのペインも隠さず表示されます。行をクリックするか Enter を押すと、そのペインへ直接移動します。`/` で名前、エージェントの種類、タブ、ワークスペース、ブランチ、パスを検索できます。検索入力中でなければ上下矢印キーまたは `j/k` で行を移動します。左右矢印キーは前後のワークスペースの最初のエージェントまたはターミナルへ移動し、端では折り返しません。検索入力中は左右矢印キーでテキストカーソルを動かします。`b/w/i/d` で blocked、working、idle、done のエージェントに絞り込み、`a` ですべてのターミナルに戻します。選択した移動先の場所とパスは一覧の下に表示されます。一覧が収まらない場合は、マウスホイール、スクロールバーのトラックのクリック、つまみのドラッグで、移動先を開かずにスクロールできます。

Esc または Ctrl+[ でワークスペースナビゲーションを終了します。Go To では、Shift が必要な配列でも `/` で検索を開けます。

open container ピッカーと open ssh host ピッカーでは、お気に入りが先頭に表示されます。`*` を押すと、選択中の行にスターを付けたり外したりできます。フィルタの入力中でも有効で、`*` がフィルタに入力されることはありません。行の ★ 列や `* favorite` ボタンをクリックしても切り替えられます。スター付きの行が最初に並び、次にデフォルトのコンテナ、その次に最近開いたホストとコンテナが続きます。まだ開いたことがない行は、サーバーが返す順序のままです。フィルタ中も並び順は保たれます。お気に入りのコンテナは、open container ピッカーの 1 段目（ホスト一覧）でホストより上にも表示され、選ぶとコンテナ一覧を経ずに直接開きます。この行で `*` を押すとスターが外れますが、ピッカーを閉じるまで ☆ 付きで残り、もう一度 `*` を押すと戻ります。お気に入りと直近 50 件の成功した接続は、このクライアントがエンドポイントごとに記憶します。

ペインへの入力はアプリが要求するキーボードモードに従います。通常のシェルには Ctrl+Shift+letter を制御バイトとして送り、表現できない Super、Hyper、Meta の組み合わせは送りません。Kitty キーボード入力を使うアプリには、要求した修飾キーとキーイベントを送ります。report-all モード以外では、修飾付き Enter、Tab、Backspace の解放レポートは送りません。テンキーと修飾キー単独の押下も転送しません。

非ラテン文字の配列では、Ctrl+W など Ctrl 単独の組み合わせに、Kitty 対応ホストが報告する物理的なベースキーを使えます。ラテン文字の配列、Ctrl+Shift、AltGr は配列上の意味を保持します。物理キーを報告しないターミナルでは、同じ配列非依存のショートカットは使えません。

## テキスト欄の編集

Herdr の名前入力、worktree のブランチ名、フィルター、コピーモードの検索欄では、カーソル位置で編集できます。以下は Herdr 自身の入力欄の操作であり、ペイン内のシェルやエージェントの操作は変わりません。

| 操作 | キー |
| --- | --- |
| 1 文字移動 | Left / Right、Ctrl+B / Ctrl+F |
| 先頭 / 末尾へ移動 | Home / End、Ctrl+A / Ctrl+E |
| 1 単語移動 | Alt+B / Alt+F |
| 前の文字を削除 | Backspace、Ctrl+H |
| 次の文字を削除 | Delete、Ctrl+D |
| 先頭 / 末尾まで切り取り | Ctrl+U / Ctrl+K |
| 前の単語を切り取り | Ctrl+W、Alt+Backspace、Ctrl+Backspace |
| 次の単語を切り取り | Alt+D |
| 最後に切り取ったテキストを挿入 | Ctrl+Y |

入力と貼り付けはカーソル位置に挿入されます。移動と削除は Unicode の書記素境界を尊重し、長い値は横にスクロールします。切り取ったテキストは現在の入力欄だけで保持し、システムのクリップボードは使いません。Alt ショートカットにはターミナルの Alt/Meta 報告が必要です。Enter と Esc は引き続きダイアログの確定とキャンセルに使います。

## コピーモード

`prefix+[` を押すと、フォーカス中のペインでコピーモードに入ります。`h/j/k/l`、tmux 形式の `w/b/e`、`{`/`}` で移動します。`/` または `?` で前方または後方のリテラル検索を開始し、`n` または `N` で同じ方向または逆方向に繰り返します。クエリに大文字が含まれる場合だけ大文字と小文字を区別します。`v` または Space で選択を開始し、`y` または Enter でコピーし、`q` または Esc でコピーせずに抜けます。Esc は終了する前に、アクティブな選択または検索を消します。コピーモードはペインのプロセスを停止しません。最下部では出力を追従し、履歴へ移動するとその位置を保ちます。マウスのドラッグ選択なら、コピーモードに入らずにそのままコピーできます。

マウスのドラッグ選択と、`v`、Space、`V` で開始した選択は、出力や再描画が続いても維持されます。選択範囲の一部が表示領域の外にある場合も同様です。コピーするのは固定されたスナップショットではなく、その範囲に現在あるテキストです。ペインのサイズ変更や通常画面と代替画面の切り替えでは、引き続き選択が解除されます。検索結果とダブルクリックによる単語選択では、内容変更のチェックが維持されます。

## ファイルビューア

`keys.open_files`（既定では未設定）、グローバルメニューの `open files`、ワークスペースメニューの `Browse files...` から調査タブを開きます。
同じ操作で最後に使ったターミナルへ戻り、再度実行すると同じワークスペースの調査を再開します。
調査の起点はターミナルで `cd` しても変わりません。
起点の変更や別の調査タブの作成には操作メニューを使います。
上段のタブ列でターミナルと調査を切り替え、下段のタブ列に固定したファイルを並べます。
一覧と本文は初期状態では上下に表示し、`F10` → `toggle split direction` で左右に切り替えます。

| キー | 操作 |
| --- | --- |
| Up / Down、クリック | 選択してプレビュー |
| Enter、ダブルクリック | ファイルをタブに固定して本文へ移動。ディレクトリは展開 |
| Space | 固定せず本文へ移動 |
| Esc | 本文の選択や検索を解除し、一覧へ戻る |
| Tab / Shift+Tab | 入力欄、結果、本文の間を移動 |
| Ctrl+PageUp / Ctrl+PageDown | 固定したファイルタブを切り替え |
| Ctrl+W | 現在のファイルタブを閉じる |
| Ctrl+P | ファイル名やパスのあいまい検索 |
| Ctrl+Shift+F | ファイル内容の検索 |
| Ctrl+H | 置換欄へ移動 |
| Ctrl+F | 表示中の本文を検索 |
| Ctrl+E | 選択したファイルを外部エディタで開く |
| Ctrl+C | 本文では選択したテキスト、一覧ではファイルをコピー |
| Ctrl+X / Ctrl+V | ファイルを切り取り／貼り付け先を指定 |
| Shift+矢印 / Shift+クリック | ファイルやテキストを範囲選択 |
| Ctrl+クリック / Insert | ファイルや検索の一致箇所を個別に選択／解除 |
| F2 / Delete | 名前変更／ゴミ箱への削除確認 |
| F5 | フォルダ一覧、パス索引、開いている本文を今すぐ更新 |
| F10、右クリック | ファイル操作、表示配置、置換差分、取り消し |

内容検索は入力が止まると更新され、検索語と対象／除外のファイルパターンを組み合わせられます。
パターンはカンマで区切り、`**/*.rs` なら起点直下とサブディレクトリの Rust ファイルを対象にします。
正規表現、大文字小文字の区別、単語単位、Git に無視されたファイルの指定を切り替えられます。
隠しファイルは対象に含め、`.git`、バイナリ、UTF-8 以外のファイル、シンボリックリンクは内容検索から除外します。
検索の上限は 50,000 ファイル、10,000 件の一致、15 秒です。
上限に達した場合は検索条件を絞ります。
本文は 8 MiB 以下の UTF-8 ファイルを表示でき、行番号を含めず元のテキストをコピーします。

一括置換では Insert または Ctrl+クリックで一致箇所を対象から外せます。
`F10` → `toggle matches in current file` ではファイル単位で対象を切り替えます。
置換欄で Enter を押すと差分を表示し、Ctrl+Enter または適用ボタンで保存します。
正規表現の置換では `$1` や `${name}` を展開し、通常の文字列置換では `$` をそのまま扱います。
1 回の置換は最大 1,000 ファイル、置換後の本文の合計は 512 KiB までです。
内容の版が変わったファイルは変更を見送ります。
`undo last replacement` は、直前の置換後から内容が変わっていないファイルを戻します。
版の照合から保存までの間にも外部編集は起こり得るため、適用中は同じファイルへの書き込みを調整してください。

ファイルのコピーや切り取りは同じ接続先の中で使い、待機中の件数を画面下部に表示します。
貼り付けと名前変更では、実行前にコピー元、移動先、同名項目の扱いを確認します。
スキップ、別名、確認したファイルの置換を選べますが、ディレクトリの統合や置換は行いません。
移動には原子的な名前変更を使い、別のボリュームへの移動はエラーを表示します。
その場合はコピー後に元の項目を明示的に削除します。
削除は接続先のゴミ箱を優先し、完全削除には別の確認が必要です。
Linux のゴミ箱には `gio`、macOS では Finder、Windows ではごみ箱を使います。

パスのコピーと送信は操作メニューに残します。
送信先のペインを表示して確認し、改行を付けずにパスを送り、調査画面を維持します。
外部編集は `$EDITOR`（Unix での既定値は `vi`、Windows は `notepad.exe`）を使い、終了後は調査へ戻ります。
SSH 越しやコンテナ内でシェルが動くペインから開いた調査は、Herdr サーバーではなくその環境のファイルシステムを閲覧します。ツリー、パス検索、プレビューは同じで、`edit file` もその環境でエディタを開きます。調査はペインではなく環境（SSH のエイリアス、またはコンテナと SSH ホストの組）に結びつきます。要求は、同じワークスペースでその環境にいる生きたペイン（フォーカス中のものを優先）を通して出します。1 つも無くなるとタブは残り、同じ環境のペインが戻るまで `no pane running in <location>` を表示します。`open_files` は、フォーカス中のペインの環境に一致するタブを開き直し、無ければ新しく開きます。環境名はタブのラベルとタイトルのパスの前に付きます。SSH 先のコンテナは `app@devbox:work` と `files · app@devbox:/work`、ローカルのコンテナは `app:work`、SSH ペインは `devbox:proj` です。
このタブでは、内容検索、置換、ファイル操作（コピー、カット、ペースト、名前変更、作成、ゴミ箱、削除）はメニュー項目もキーも残りますが、押すと `not available inside <location>` と表示するだけです。プレビューと展開中フォルダの一覧の更新は 1 秒ごとではなく 5 秒ごとで、要求は 1 つずつで、他の要求の実行中は行いません。パスの送信とパスのコピーは、その環境から見たパスをそのまま使います。送信できるのは、フォーカス中のペインがタブと同じ環境で動いているときだけです。これはホストのタブにも当てはまり、そうでなければ `terminal destination is not in <location>` と表示します。シェルなしで復元されたペインはホストのペインとして扱います。`pane.directory.*` を持たない古いサーバーでは、そのペインについても従来どおりホスト側を一覧し、`host:` を付けて示します。ペインの中でさらに入力した `ssh` や `docker exec` の入れ子の環境は追跡しません。
起点、固定したファイル、閲覧位置、検索条件、配置はクライアント側に保存します。
再開時は内容と検索結果を読み直し、コピー待ちや取り消し履歴は復元しません。
外部変更は本文へ反映しますが、テキストを選択している間は更新を保留します。1 秒ごと（SSH やコンテナのタブでは 5 秒ごと）に、ルートと表示中の展開フォルダの一覧を順に取り直し、ツリーを閉じたり読み込み直したりせずに差分だけを反映します。フォルダの項目が増減したときはパス索引も取り直しますが、間隔は 10 秒（SSH やコンテナのタブでは 30 秒）以上空けます。`F5`、`F10` → `refresh files`、`[F5 refresh]` ボタンは、この更新を索引も含めて今すぐ始め、開いている本文も読み直します。内容検索の結果は `F10` → `refresh content search` で更新します。

調査画面のキーはターミナルの設定と分けて変更できます。

```toml
[ui.file_workbench_keys]
next_file = "alt+right"
previous_file = "alt+left"
```

`file.read` に対応していないサーバーでは従来のパス選択画面を使い、Enter と Space のパス送信も維持します。

## 何でも変更できる

プレフィックス自体を含め、すべてのバインドは設定可能です:

```toml
[keys]
prefix = "ctrl+a"
```

## プレフィックスなしで運用する

Herdr のアクションを、プレフィックス不要の直接コードに割り当てることもできます。難しいのはどのコードが安全かを知ることです。ターミナル、シェル、デスクトップ環境がすでにキーボードの大半を占有しているからです。

どんなコードでもバインドにできます: `ctrl+j`、`alt+k`、手に馴染むものなら何でも。ただしコードが Herdr に届くまでには 3 つの層を通り抜ける必要があります: オペレーティングシステム、外側のターミナル (Ghostty、iTerm2 などは独自のデフォルトを持ちます)、そしてペイン内で動くプログラムです。`ctrl+j` は Herdr まで問題なく届きますが、シェルやエディタはそれを Enter として扱います。`alt+k` は Linux では空いていますが、macOS ではほとんどのターミナルで特殊文字に合成されます。これらの系統からコードを選ぶ場合は、自分のターミナルと OS のショートカットと衝突しないか確認してください。

私たちは Ghostty、iTerm2、Terminal.app、kitty、WezTerm、Alacritty、Warp、Windows Terminal、GNOME Terminal、Konsole のデフォルトキーバインドと、GNOME および KDE のグローバルショートカットを調査しました。ほぼどこでも使われていない修飾キーの系統がひとつあります: `ctrl+alt` です。ターミナルはこれを空けたままにしており、素の `alt` コードを阻む macOS の option キー合成の影響も受けず、モダンなキーボードプロトコルのないターミナルでも送信されます。安全なデフォルトとしてお勧めしますが、選択はあなた次第です。

この設定はプレフィックスバインドを維持したまま、直接コードを追加します:

```toml
[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]
```

いくつかの `ctrl+alt` コードは他で使われています。これらは避けてください:

| コード | 使用しているもの |
| --- | --- |
| `ctrl+alt+arrows` | GNOME のワークスペース切り替え、Ghostty と Konsole のデフォルト |
| `ctrl+alt+t` | Ubuntu と Fedora の「ターミナルを起動」 |
| `ctrl+alt+l` / `ctrl+alt+a` | KDE のロック画面 / アテンションウィンドウ |
| `ctrl+alt+s` / `ctrl+alt+u` | Konsole |
| `ctrl+alt+f1..f12` | Linux の仮想コンソール切り替え |

直接コードを押しても何も起きない場合、Herdr に届く前にターミナルかデスクトップ環境がそれを消費しています。どちらかを再設定してください: ターミナルの設定でそのコードを解放するか、Herdr で別のコードを選びます。
