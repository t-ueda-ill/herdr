Herdr はマウスネイティブです。キーバインドをひとつも覚えなくても、ペイン、タブ、ワークスペース、エージェントをクリックし、分割境界をドラッグし、右クリックメニューを使えます。キーボード操作は任意のレイヤーであり、必須ではありません。

## プレフィックスとは何か

ターミナルマルチプレクサは、ターミナルとその中で動くプログラムの間に位置します。プログラムはすでにほとんどのキーの組み合わせを使っています: `ctrl+c` は中断、`ctrl+r` は履歴検索、エディタは残りのほぼすべてを占有します。もし Herdr がよく使われるキーを直接奪えば、中のプログラムを壊してしまいます。

プレフィックスはこれを解決します。プレフィックスキー (デフォルト `ctrl+b`) を押すと、次のキー入力はターミナルではなく Herdr に送られます。`prefix+c` は「`ctrl+b` を押して離し、次に `c` を押す」という意味です。何十ものキーを予約する代わりに、ひとつだけ予約します。

いつでも `prefix+?` を押すと、すべての有効なバインドが表示されます。キーバインドヘルプで `/` を押すと、アクションとショートカットを絞り込めます。Backspace でフィルターを編集し、`ctrl+u` でクリアできます。ファイルワークベンチがキー入力を受け取っているあいだは、ヘルプのポップアップ外のキーとクリックはワークベンチに渡り、`Esc` か `?` でヘルプを閉じます。`/` もワークベンチに渡るため、フィルターに入力するにはヘルプのポップアップ内のフィルター行をクリックしてフォーカスします。フィルターにフォーカスがあるあいだは、入力とキーはヘルプが受け取ります。

## まずこの 5 つを覚える

| アクション | キー |
| --- | --- |
| 新しいタブ | `prefix+c` |
| 右 / 下に分割 | `prefix+v` / `prefix+minus` |
| ペイン間の移動 | `prefix+h/j/k/l` |
| ワークスペースナビゲーション | `prefix+w` |
| すべてを動かしたままデタッチ | `prefix+q` |

これで日常の移動のほとんどをカバーできます。それ以外はマウスのままで大丈夫です。

## 残りはタスク別に

ペイン:

| アクション | キー |
| --- | --- |
| フォーカス中のペインをズーム | `prefix+z` |
| ペインを閉じる | `prefix+x` |
| ペインを入れ替える | `prefix+shift+h/j/k/l` |
| リサイズモード | `prefix+r` |
| コピーモード | `prefix+[` |

タブ:

| アクション | キー |
| --- | --- |
| 次 / 前のタブ | `prefix+n` / `prefix+p` |
| タブ 1–9 にジャンプ | `prefix+1..9` |
| タブの名前を変更 | `prefix+shift+t` |
| タブを閉じる | `prefix+shift+x` |

ワークスペースとセッション:

| アクション | キー |
| --- | --- |
| 新しいワークスペース | `prefix+shift+n` |
| ワークスペースの名前を変更 | `prefix+shift+w` |
| ワークスペースを閉じる | `prefix+shift+d` |
| Goto ピッカー | `prefix+g` |
| サイドバーの表示切り替え | `prefix+b` |

完全なキーマップとバインドの構文は[キーバインドリファレンス](/ja/docs/configuration/#キーバインド)にあります。

Goto ピッカー (`prefix+g`) は、各エージェントとターミナルをワークスペースごとに一行ずつ表示します。分割タブのペインも隠さず表示されます。行をクリックするか Enter を押すと、そのペインへ直接移動します。`/` で名前、エージェントの種類、タブ、ワークスペース、ブランチ、パスを検索できます。検索入力中でなければ上下矢印キーまたは `j/k` で行を移動します。左右矢印キーは前後のワークスペースの最初のエージェントまたはターミナルへ移動し、端では折り返しません。検索入力中は左右矢印キーでテキストカーソルを動かします。`b/w/i/d` で blocked、working、idle、done のエージェントに絞り込み、`a` ですべてのターミナルに戻します。選択した移動先の場所とパスは一覧の下に表示されます。一覧が収まらない場合は、マウスホイール、スクロールバーのトラックのクリック、つまみのドラッグで、移動先を開かずにスクロールできます。

Esc または Ctrl+[ でワークスペースナビゲーションを終了します。Go To では、Shift が必要な配列でも `/` で検索を開けます。

open container ピッカーと open ssh host ピッカーでは、お気に入りが先頭に表示されます。`*` を押すと、選択中の行にスターを付けたり外したりできます。フィルタの入力中でも有効で、`*` がフィルタに入力されることはありません。行の ★ 列や `* favorite` ボタンをクリックしても切り替えられます。スター付きの行が最初に並び、次にデフォルトのコンテナ、その次に最近開いたホストとコンテナが続きます。まだ開いたことがない行は、サーバーが返す順序のままです。フィルタ中も並び順は保たれます。お気に入りのコンテナは、open container ピッカーの 1 段目（ホスト一覧）でホストより上にも表示され、選ぶとコンテナ一覧を経ずに直接開きます。この行で `*` を押すとスターが外れますが、ピッカーを閉じるまで ☆ 付きで残り、もう一度 `*` を押すと戻ります。お気に入りと直近 50 件の成功した接続は、このクライアントがエンドポイントごとに記憶します。

ペインへの入力はアプリが要求するキーボードモードに従います。通常のシェルには Ctrl+Shift+letter を制御バイトとして送り、表現できない Super、Hyper、Meta の組み合わせは送りません。Kitty キーボード入力を使うアプリには、要求した修飾キーとキーイベントを送ります。report-all モード以外では、修飾付き Enter、Tab、Backspace の解放レポートは送りません。テンキーと修飾キー単独の押下も転送しません。

非ラテン文字の配列では、Ctrl+W など Ctrl 単独の組み合わせに、Kitty 対応ホストが報告する物理的なベースキーを使えます。ラテン文字の配列、Ctrl+Shift、AltGr は配列上の意味を保持します。物理キーを報告しないターミナルでは、同じ配列非依存のショートカットは使えません。

## テキスト欄の編集

Herdr の名前入力、worktree のブランチ名、フィルター、コピーモードの検索欄では、カーソル位置で編集できます。以下は Herdr 自身の入力欄の操作であり、ペイン内のシェルやエージェントの操作は変わりません。

| 操作 | キー |
| --- | --- |
| 1 文字移動 | Left / Right、Ctrl+B / Ctrl+F |
| 先頭 / 末尾へ移動 | Home / End、Ctrl+A / Ctrl+E |
| 1 単語移動 | Alt+B / Alt+F |
| 前の文字を削除 | Backspace、Ctrl+H |
| 次の文字を削除 | Delete、Ctrl+D |
| 先頭 / 末尾まで切り取り | Ctrl+U / Ctrl+K |
| 前の単語を切り取り | Ctrl+W、Alt+Backspace、Ctrl+Backspace |
| 次の単語を切り取り | Alt+D |
| 最後に切り取ったテキストを挿入 | Ctrl+Y |

入力と貼り付けはカーソル位置に挿入されます。移動と削除は Unicode の書記素境界を尊重し、長い値は横にスクロールします。切り取ったテキストは現在の入力欄だけで保持し、システムのクリップボードは使いません。Alt ショートカットにはターミナルの Alt/Meta 報告が必要です。Enter と Esc は引き続きダイアログの確定とキャンセルに使います。

## コピーモード

`prefix+[` を押すと、フォーカス中のペインでコピーモードに入ります。`h/j/k/l`、tmux 形式の `w/b/e`、`{`/`}` で移動します。`/` または `?` で前方または後方のリテラル検索を開始し、`n` または `N` で同じ方向または逆方向に繰り返します。クエリに大文字が含まれる場合だけ大文字と小文字を区別します。`v` または Space で選択を開始し、`y` または Enter でコピーし、`q` または Esc でコピーせずに抜けます。Esc は終了する前に、アクティブな選択または検索を消します。コピーモードはペインのプロセスを停止しません。最下部では出力を追従し、履歴へ移動するとその位置を保ちます。マウスのドラッグ選択なら、コピーモードに入らずにそのままコピーできます。

マウスのドラッグ選択と、`v`、Space、`V` で開始した選択は、出力や再描画が続いても維持されます。選択範囲の一部が表示領域の外にある場合も同様です。コピーするのは固定されたスナップショットではなく、その範囲に現在あるテキストです。ペインのサイズ変更や通常画面と代替画面の切り替えでは、引き続き選択が解除されます。検索結果とダブルクリックによる単語選択では、内容変更のチェックが維持されます。

## ファイルビューア

`keys.open_files`（既定は `prefix+f`）、グローバルメニューの `open files`、ワークスペースメニューの `Browse files...` から files タブを開きます。
files タブは最初はターミナルの左に並べて開きます。ワークスペースで初めて開く files タブは、最後に使った置き場所で開きます。境界線をドラッグするか、ファイル側がキー入力を受け取っているときに `prefix+r` の後で `h`/`l`（下に置いたときは `j`/`k`）を押すと、幅を変えられます。files メニューか `prefix+shift+h` / `prefix+shift+l` / `prefix+shift+j` で置き場所を変えられ（`dock left` / `dock right` / `dock bottom`）、メニューか `prefix+z` でターミナルを覆う全面表示に切り替えられます（`show full screen` / `show split`）。この選択と置き場所、幅はワークスペースごとに覚えています。ターミナルが 40 桁、ファイル側が 24 桁（下に置いたときは 8 行と 6 行）に満たない場合は、全面表示になり、その幅より少し余裕ができた時点で横並びに戻ります。境界付近でウィンドウの大きさを変えても表示が行き来しないようにするためです。
クリックした側がキー入力を受け取ります。`prefix+h/j/k/l`（navigate モードでは `h/j/k/l`）でも行き来できます。ファイル側に接する端のターミナルペインでファイル側へ向かうキーを押すとファイル側へ、逆向きのキーでターミナルへキー入力が移ります。ズーム中のタブでは、これらのキーはペイン間の移動に使います。ファイル一覧で何も選択していないときに `Esc` を押しても、ファイル側を表示したままターミナルへキー入力を戻します。
`keys.open_files` は、ターミナルがキー入力を受け取っているときは横の files タブへ移し、files タブが受け取っているときは files タブを隠し、表示していなければ同じワークスペースの files タブを再開します。全面表示では files タブと最後に使ったターミナルを切り替えます。
files タブの起点はターミナルで `cd` しても変わりません。
起点の変更や別の files タブの作成は、files メニューから行います。
上段のタブ列でターミナルと files タブを切り替えます。
右クリックメニューはポインタの位置に開き、クリックした対象（ファイル、フォルダ、ツリーの空いている所、検索欄と検索結果、詳細欄）に使える操作を並べます。`F10` は、選択中の対象（選択中のファイル、フォルダ、内容検索の一致箇所）の同じメニューを選択行の位置に開きます。以下の「`F10` → 項目」は、その項目が対象とするもののメニューにある項目を指します。
files メニューには files タブ全体への操作（起点直下への作成と貼り付け、更新、無視されたファイルの表示、詳細欄の表示、起点の変更、files タブを開く／閉じる、置き場所）が並びます。タイトル行の `≡` ボタン、`Shift+F10`、タイトル行や上段のタブ列の files タブ、ツリーの空いている所の右クリックで開きます。

最下行には、キー入力を受け取っている場所でよく使うキーを表示します。一覧で `?` を押すとすべてのキーを表示します。メニューの各項目の右にもキーを表示します。

| キー | 操作 |
| --- | --- |
| Up / Down、`j` / `k`、クリック | 選択 |
| Left / Right、`h` / `l` | フォルダを折りたたむ／展開する。ファイルや閉じたフォルダで Left を押すと親を選択 |
| Home / End、`gg` / `G` | 先頭／末尾の行 |
| PageUp / PageDown | 1 画面ぶん上／下 |
| Ctrl+U / Ctrl+D | 半画面ぶん上／下 |
| `n` / `N` | 内容検索の結果で次／前のファイル |
| Enter、ダブルクリック | ファイルを `$EDITOR` で開く（内容検索の一致箇所ではその行から）。ディレクトリは展開 |
| Space | ファイルをページャで開く。ディレクトリは展開 |
| Esc | 入力欄から抜け、マークしたファイルを解除し、ターミナルへキー入力を戻す |
| Tab / Shift+Tab | 入力欄と結果の間を移動 |
| `/` | ツリーをパスで絞り込む |
| Ctrl+P | ファイル名やパスのあいまい検索 |
| Ctrl+Shift+F | ファイル内容の検索 |
| Alt+R / Alt+C / Alt+W / Alt+I | 内容検索で正規表現／大文字小文字の区別／単語単位／無視されたファイルを切り替え |
| Ctrl+H | 置換欄へ移動 |
| Ctrl+E | 選択したファイルを外部エディタで開く |
| `K` | 詳細欄の表示／非表示 |
| `a` / `A` | 選択中のフォルダに新しいファイル／ディレクトリ |
| `y` | パスをコピー |
| `t` | パスをターミナルへ送る |
| `C` | 選択中のフォルダ（ファイルならそのフォルダ）を起点にする |
| Backspace | 起点を親へ広げる |
| `.` / `i` | ドットファイル／無視されたファイルを表示 |
| Ctrl+C | 選択したファイルをコピー |
| Ctrl+X / Ctrl+V | ファイルを切り取り／貼り付け先を指定 |
| Shift+矢印 / Shift+クリック | ファイルを範囲選択 |
| `m`、Insert、Ctrl+クリック | ファイルや検索の一致箇所を個別に選択／解除 |
| Ctrl+A | 一覧のファイルをすべてマーク |
| F2 / Delete / Shift+Delete | 名前変更／ゴミ箱への削除確認／完全削除の確認 |
| F5 | フォルダ一覧、パス索引、詳細欄を今すぐ更新 |
| F10、Alt+M、右クリック | 選択中の対象、またはクリックした対象への操作 |
| Shift+F10、`≡` | files メニュー |
| `?` | 設定を反映した files のキー一覧 |

`ui.file_workbench_keys` で files のキーを名前ごとに置き換えられます（例: `details = "ctrl+t"`）。置き換えた 1 文字のキーは効かなくなりますが、矢印、Home/End、PageUp/PageDown はそのまま使えます。名前は `pin`（Enter）、`read`（Space）、`down`、`up`、`collapse`、`expand`、`top`、`bottom`、`half_page_down`、`half_page_up`、`mark`、`details`、`next_file`、`previous_file`、`new_file`、`new_directory`、`copy_path`、`send_path`、`change_root`、`find_files`、`search`、`replace`、`toggle_regex`、`toggle_case`、`toggle_whole_word`、`toggle_ignored`、`edit`、`copy`、`cut`、`paste`、`select_all`、`rename`、`delete`、`delete_permanently`、`actions`、`files_menu`、`refresh` です。

内容検索は入力が止まると更新され、検索語と対象／除外のファイルパターンを組み合わせられます。
パターンはカンマで区切り、`**/*.rs` なら起点直下とサブディレクトリの Rust ファイルを対象にします。
正規表現、大文字小文字の区別、単語単位、Git に無視されたファイルの指定を切り替えられます。
隠しファイルは対象に含め、`.git`、バイナリ、UTF-8 以外のファイル、シンボリックリンクは内容検索から除外します。
検索の上限は 50,000 ファイル、10,000 件の一致、15 秒です。
上限に達した場合は検索条件を絞ります。

一括置換では Insert または Ctrl+クリックで一致箇所を対象から外せます。
`F10` → `toggle matches in current file` ではファイル単位で対象を切り替えます。
置換欄で Enter を押すと差分を表示し、Ctrl+Enter または適用ボタンで保存します。
正規表現の置換では `$1` や `${name}` を展開し、通常の文字列置換では `$` をそのまま扱います。
1 回の置換は最大 1,000 ファイル、置換後の本文の合計は 512 KiB までです。
内容の版が変わったファイルは変更を見送ります。
`undo last replacement` は、直前の置換後から内容が変わっていないファイルを戻します。
版の照合から保存までの間にも外部編集は起こり得るため、適用中は同じファイルへの書き込みを調整してください。

ファイルのコピーや切り取りは同じ接続先の中で使い、待機中の件数を画面下部に表示します。
貼り付けと名前変更では、実行前にコピー元、移動先、同名項目の扱いを確認します。
スキップ、別名、確認したファイルの置換を選べますが、ディレクトリの統合や置換は行いません。
移動には原子的な名前変更を使い、別のボリュームへの移動はエラーを表示します。
その場合はコピー後に元の項目を明示的に削除します。
削除は接続先のゴミ箱を優先し、完全削除には別の確認が必要です。
Linux のゴミ箱には `gio`、macOS では Finder、Windows ではごみ箱を使います。

デスクトップからファイルやフォルダを一覧にドロップすると、選択中のフォルダ（ファイルを選択しているときはそのフォルダ、何も選択していないときはルート）へコピーします。
ドロップとして扱うのは一覧にフォーカスがあるときだけです。パス検索などのテキスト欄では、今までどおりパスが文字として入ります。
ダイアログには送り先、件数と合計サイズ、送り先に同じ名前がある項目を表示します。衝突がなければ `upload`、あれば `replace`（上書き）、`keep both`（別名）、`cancel`（中止）から選びます（左右キーと Enter、またはボタンのクリック）。
終わるとそのフォルダを読み直し、最初に追加した項目を選択します。
タブがどのファイルシステムを表示していても（SSH やコンテナの環境、サーバー自身のホスト、このマシンで動くサーバーを含む）、このクライアントがファイルを送り、サーバーが最後にまとめて公開します。失敗や中止では何も残らず、`keep both` の別名は `name (1).ext` になり、`replace` はフォルダも置き換えます。右上の進捗カードをクリックすると、公開が始まるまでは中止できます。
`ui.upload_on_drop = false` でドロップを無効にでき、`ui.upload_max_bytes` と `ui.upload_max_entries` を超えるアップロードは拒否します。詳しくは[ファイルのドロップ](/ja/docs/persistence-remote/#ファイルのドロップ)を参照してください。

`F10` → `download…` は、選択したファイルとフォルダ（複数可、フォルダは再帰的に）を、サーバーのマシンではなく、このクライアントが動くマシンへ保存します。操作したクライアントのマシンにだけ保存されます。ダイアログには保存先のフォルダが出ます。既定は `~/Downloads`（Linux では XDG のダウンロードフォルダ、Windows では Downloads の既知のフォルダ）で、他の入力欄と同じく編集できます。`~` と、このマシンの形式のパスを受け付けます。最後の名前が同じ項目や、大文字小文字だけが違う項目を一緒に選ぶと、何も始まる前に断ります。保存先の中の隠しフォルダ `.herdr-upload-*` で組み立ててから一度に公開するので、失敗や中止では何も残りません。同じ名前があるときは `name (1).ext` になります。選択したシンボリックリンクは辿ってリンク先の中身を保存し、フォルダの中のリンクはリンクのまま保存し、FIFO、ソケット、デバイスは飛ばします。読めない項目や、このマシンに置けない名前の項目は、警告を通知に出して飛ばします。読んでいる間にファイルが変わると、ダウンロード全体が失敗します。右上の進捗カードはアップロードと共用で（転送は同時に 1 つだけ）、保存が始まるまではクリックで中止できます。16 GiB か 100,000 件を超えるダウンロードは拒否します。[ファイルのダウンロード](/ja/docs/persistence-remote/#ファイルのダウンロード)を参照してください。

ファイル、内容検索の一致箇所、詳細欄のメニューには、パスのコピー（`copy path`）と送信（`send path to terminal…`）、`edit file`、`view file` があり、フォルダのメニューにはパスのコピーがあります。
送信先のペインを表示して確認し、改行を付けずにパスを送り、files タブを維持します。
`edit file`（Enter）は `$EDITOR`（Unix での既定値は `vi`、Windows は `notepad.exe`）を使い、`view file`（Space）は `$PAGER` を使います。`$PAGER` が無ければ `less`、`more` の順に探し、どちらも無ければ `cat` で表示します。短いファイルがすぐ消えないよう、`less` 以外のページャは終了後に `[press Enter]` で待ち、`less` には `-+F` を付けて `LESS=-F` でもすぐ終了しないようにします。どちらもフォーカス中のペインの上に開き、内容検索の一致箇所では、プログラムが `+line` 引数を受け付けるなら該当行から表示し、終了後は files タブへ戻ります。`pane.open_file`（SSH やコンテナのタブでは `pane.directory.open_file`）を持たないサーバーでは、Windows のサーバーも含め、どちらもエディタでファイルの先頭から開きます。

一覧の下の詳細欄には、選択中の項目の情報を表示します。ファイルなら名前、サイズ、更新日時、パーミッション、所有者、フォルダなら項目数（`..` や何も選択していないときは表示中のフォルダ）、ファイルをマークしている間は件数と合計サイズ、内容検索の一致箇所ではパス、行番号、前後の行です。高さは表示する行数に合わせ、既定では 8 行と files タブの 3 分の 1 までに収めます。一覧が 5 行未満になるときは隠します。files メニューの `toggle details` で表示と非表示を切り替えられ、この選択はクライアントごとに保存します。情報は、選択が止まってから約 150 ms 後、一覧の更新日時が新しくなったとき、`F5` の後、エディタやページャを閉じた後に取り直します。各行の内容はテンプレートで変えられます。[Files の詳細表示](/ja/docs/configuration/#files-の詳細表示)を参照してください。
SSH 越しやコンテナ内でシェルが動くペインから開いた files タブは、Herdr サーバーではなくその環境のファイルシステムを閲覧します。ツリー、パス検索、詳細欄は同じで、`edit file` と `view file` もその環境のログインシェルの設定に従ってエディタとページャを開きます。files タブはペインではなく環境（SSH のエイリアス、またはコンテナと SSH ホストの組）に結びつきます。要求は、同じワークスペースでその環境にいる生きたペイン（フォーカス中のものを優先）を通して出します。1 つも無くなるとタブは残り、同じ環境のペインが戻るまで `no pane running in <location>` を表示します。`open_files` は、フォーカス中のペインの環境に一致するタブを開き直し、無ければ新しく開きます。開き直したタブは、ペインの現在のディレクトリが分かり、ルートと異なるときにルートをそこへ移します。タブを表示している間、ルートはペインに追従しません。環境名はタブのラベルとタイトルのパスの前に付きます。SSH 先のコンテナは `app@devbox:work` と `files · app@devbox:/work`、ローカルのコンテナは `app:work`、SSH ペインは `devbox:proj` です。
このタブでは、内容検索、置換、ファイル操作（コピー、カット、ペースト、名前変更、作成、ゴミ箱、削除）はメニュー項目もキーも残りますが、押すと `not available inside <location>` と表示するだけです。ただし、一覧へのファイルのドロップはその環境へアップロードし、`download…` もその環境で動いて、タブの環境にある生きたペインを通して読みます。展開中フォルダの一覧の更新は 1 秒ごとではなく 5 秒ごとで、要求は 1 つずつで、他の要求の実行中は行いません。パスの送信とパスのコピーは、その環境から見たパスをそのまま使います。送信できるのは、フォーカス中のペインがタブと同じ環境で動いているときだけです。これはホストのタブにも当てはまり、そうでなければ `terminal destination is not in <location>` と表示します。シェルなしで復元されたペインはホストのペインとして扱います。`pane.directory.*` を持たない古いサーバーでは、そのペインについても従来どおりホスト側を一覧し、`host:` を付けて示します。ペインの中でさらに入力した `ssh` や `docker exec` の入れ子の環境は追跡しません。
起点、検索条件、ワークスペースごとの並べて表示か全面表示かの選択とその位置・幅はクライアント側に保存します。
再開時は一覧と検索結果を読み直し、コピー待ちや取り消し履歴は復元しません。
ルートの移動: ルートに親フォルダがあるとき、ツリーの先頭に `..` 行を表示します。`Enter` かダブルクリックで、`Backspace` と同じくルートを 1 つ上げ、元のフォルダを選択します。フォルダのメニューの `open as root` は、そのフォルダを新しいルートにします。SSH やコンテナのタブでも使えます。パスを入力するときは、ツリーの空いている所か `..` 行のメニューにある `change root` を使います。`..` 行は送信、コピー、ファイル操作の対象になりません。

1 秒ごと（SSH やコンテナのタブでは 5 秒ごと）に、ルートと表示中の展開フォルダの一覧を順に取り直し、ツリーを閉じたり読み込み直したりせずに差分だけを反映します。フォルダの項目が増減したときはパス索引も取り直しますが、間隔は 10 秒（SSH やコンテナのタブでは 30 秒）以上空けます。`F5`、ツリーの空いている所のメニューにある `refresh files`、`[F5 refresh]` ボタンは、この更新を索引も含めて今すぐ始め、詳細欄の情報も取り直します。内容検索の結果は、内容検索の入力欄や結果のメニューにある `refresh content search` で更新します。

files タブのキーはターミナルの設定と分けて変更できます。

```toml
[ui.file_workbench_keys]
refresh = "ctrl+r"
edit = "alt+e"
```

`file.read` に対応していないサーバーでは従来のパス選択画面を使い、Enter と Space のパス送信も維持します。

## 何でも変更できる

プレフィックス自体を含め、すべてのバインドは設定可能です:

```toml
[keys]
prefix = "ctrl+a"
```

## プレフィックスなしで運用する

Herdr のアクションを、プレフィックス不要の直接コードに割り当てることもできます。難しいのはどのコードが安全かを知ることです。ターミナル、シェル、デスクトップ環境がすでにキーボードの大半を占有しているからです。

どんなコードでもバインドにできます: `ctrl+j`、`alt+k`、手に馴染むものなら何でも。ただしコードが Herdr に届くまでには 3 つの層を通り抜ける必要があります: オペレーティングシステム、外側のターミナル (Ghostty、iTerm2 などは独自のデフォルトを持ちます)、そしてペイン内で動くプログラムです。`ctrl+j` は Herdr まで問題なく届きますが、シェルやエディタはそれを Enter として扱います。`alt+k` は Linux では空いていますが、macOS ではほとんどのターミナルで特殊文字に合成されます。これらの系統からコードを選ぶ場合は、自分のターミナルと OS のショートカットと衝突しないか確認してください。

私たちは Ghostty、iTerm2、Terminal.app、kitty、WezTerm、Alacritty、Warp、Windows Terminal、GNOME Terminal、Konsole のデフォルトキーバインドと、GNOME および KDE のグローバルショートカットを調査しました。ほぼどこでも使われていない修飾キーの系統がひとつあります: `ctrl+alt` です。ターミナルはこれを空けたままにしており、素の `alt` コードを阻む macOS の option キー合成の影響も受けず、モダンなキーボードプロトコルのないターミナルでも送信されます。安全なデフォルトとしてお勧めしますが、選択はあなた次第です。

この設定はプレフィックスバインドを維持したまま、直接コードを追加します:

```toml
[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]
```

いくつかの `ctrl+alt` コードは他で使われています。これらは避けてください:

| コード | 使用しているもの |
| --- | --- |
| `ctrl+alt+arrows` | GNOME のワークスペース切り替え、Ghostty と Konsole のデフォルト |
| `ctrl+alt+t` | Ubuntu と Fedora の「ターミナルを起動」 |
| `ctrl+alt+l` / `ctrl+alt+a` | KDE のロック画面 / アテンションウィンドウ |
| `ctrl+alt+s` / `ctrl+alt+u` | Konsole |
| `ctrl+alt+f1..f12` | Linux の仮想コンソール切り替え |

直接コードを押しても何も起きない場合、Herdr に届く前にターミナルかデスクトップ環境がそれを消費しています。どちらかを再設定してください: ターミナルの設定でそのコードを解放するか、Herdr で別のコードを選びます。
