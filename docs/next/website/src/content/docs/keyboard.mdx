Herdr is mouse-native. You can click panes, tabs, workspaces, and agents, drag split borders, and use right-click menus without learning a single keybinding. Keyboard control is optional.

## What the prefix is

A terminal multiplexer sits between your terminal and the programs running inside it. Those programs already use most key combinations: `ctrl+c` interrupts, `ctrl+r` searches history, editors claim nearly everything else. If Herdr grabbed common keys directly, it would break the programs inside it.

The prefix solves this. Press the prefix key, default `ctrl+b`, and the next keypress goes to Herdr instead of your terminal. `prefix+c` means: press `ctrl+b`, release, then press `c`. Herdr reserves one key instead of dozens.

Press `prefix+?` at any time to see every active binding. Press `/` in the keybind help to filter actions and shortcuts; use Backspace to edit the filter or `ctrl+u` to clear it. While the files workbench has the keys, keys and clicks outside the help popup go to the workbench, and `Esc` or `?` closes the help; `/` goes to the workbench too, so click the filter line in the help popup to focus it; while the filter has focus, typing and keys stay with the help.

## Learn these five first

| Action | Key |
| --- | --- |
| New tab | `prefix+c` |
| Split right / down | `prefix+v` / `prefix+minus` |
| Move between panes | `prefix+h/j/k/l` |
| Workspace navigation | `prefix+w` |
| Detach, leave everything running | `prefix+q` |

These cover most daily movement. Everything else can stay on the mouse.

## The rest, by task

Panes:

| Action | Key |
| --- | --- |
| Zoom the focused pane | `prefix+z` |
| Close pane | `prefix+x` |
| Swap panes | `prefix+shift+h/j/k/l` |
| Resize mode | `prefix+r` |
| Copy mode | `prefix+[` |

Tabs:

| Action | Key |
| --- | --- |
| Next / previous tab | `prefix+n` / `prefix+p` |
| Jump to tab 1–9 | `prefix+1..9` |
| Rename tab | `prefix+shift+t` |
| Close tab | `prefix+shift+x` |

Workspaces and session:

| Action | Key |
| --- | --- |
| New workspace | `prefix+shift+n` |
| Rename workspace | `prefix+shift+w` |
| Close workspace | `prefix+shift+d` |
| Goto picker | `prefix+g` |
| Toggle sidebar | `prefix+b` |

The full keymap and the binding syntax live in the [keybinding reference](/docs/configuration/#keybindings).

The Goto picker (`prefix+g`) lists each agent or terminal on its own row, grouped by workspace. Split tabs never hide their panes behind another row. Click a row or press Enter to jump directly to it. Press `/` to search names, agent kinds, tabs, workspaces, branches, or paths; use Up/Down or `j/k` to move between rows when not typing a search. Left/Right jumps to the first agent or terminal in the previous/next workspace section, without wrapping. While editing a search, Left/Right moves the text cursor instead. Outside search, `b/w/i/d` filter blocked, working, idle, or done agents, and `a` shows all terminals again. The selected destination's location and path appear below the list. When the list overflows, use the mouse wheel, click the scrollbar track, or drag its thumb to scroll without opening a destination.

Press Esc or Ctrl+[ to leave workspace navigation. In the Go To picker, `/` also opens search on layouts that require Shift to type it.

The open container and open ssh host pickers keep your favorites at the top. Press `*` to star or unstar the selected row; this also works while you are typing a filter, and `*` never goes into the filter. You can also click a row's ★ column or the `* favorite` button. Starred rows list first, then the default container, then the hosts and containers you opened most recently; rows you have never opened keep the order the server lists them in. The order is kept while filtering. Favorite containers also appear above the hosts on the first step of the open container picker (the host list); selecting one opens it directly without the container list. Pressing `*` on such a row unstars it but keeps it listed with ☆ until the picker closes, and pressing `*` again restores it. Favorites and the last 50 successful opens are remembered per endpoint by this client.

Pane input follows the keyboard modes requested by the app. Plain shells receive Ctrl+Shift+letter as its control byte; Super, Hyper, and Meta chords are dropped when the pane cannot represent them. Apps using Kitty keyboard input receive the modifiers and key events they request. Without report-all mode, modified Enter, Tab, and Backspace do not receive release reports. Keypad keys and modifier-only presses are not forwarded.

On non-Latin layouts, Ctrl-only shortcuts such as Ctrl+W can use the physical base key reported by a Kitty-capable host. Latin layout characters, Ctrl+Shift chords, and AltGr keep their layout meaning. Terminals that do not report physical keys cannot provide the same layout-independent shortcuts.

## Editing text fields

Herdr's naming dialogs, worktree branch fields, filters, and copy-mode search support editing at the cursor. These shortcuts apply to Herdr-owned fields, not to the shell or agent inside a pane.

| Action | Keys |
| --- | --- |
| Move one character | Left / Right, Ctrl+B / Ctrl+F |
| Move to the beginning / end | Home / End, Ctrl+A / Ctrl+E |
| Move one word | Alt+B / Alt+F |
| Delete the previous character | Backspace, Ctrl+H |
| Delete the next character | Delete, Ctrl+D |
| Cut to the beginning / end | Ctrl+U / Ctrl+K |
| Cut the previous word | Ctrl+W, Alt+Backspace, Ctrl+Backspace |
| Cut the next word | Alt+D |
| Insert the last cut text | Ctrl+Y |

Typing and paste insert at the cursor. Movement and deletion respect Unicode grapheme boundaries, and long values scroll horizontally. Cut text stays within the current field; it does not use the system clipboard. Alt shortcuts require the terminal to report Alt/Meta. Enter and Esc retain the dialog's confirm and cancel behavior.

## Copy mode

Press `prefix+[` to enter copy mode for the focused pane. Use `h/j/k/l`, tmux-style `w/b/e` and big-word `W/B/E`, `{`/`}`, `PageUp`/`PageDown`, `ctrl+b`/`ctrl+f`, and `ctrl+u`/`ctrl+d` to move. Press `/` or `?` for forward or backward literal search, then `n` or `N` to repeat in the same or opposite direction. Search is case-insensitive unless the query contains an uppercase letter. Use `v` or Space to start a selection, `y` or Enter to copy it, and `q` or Esc to leave without copying. Esc clears an active selection or search before exiting. Copy mode does not pause the pane process: output remains live, follows at the bottom, and stays pinned when you navigate into history. The configured prefix keeps its normal meaning in copy mode; with the default prefix, `ctrl+b` enters prefix mode instead of paging up, so use a different prefix if you want `ctrl+b` for copy-mode page-up. Mouse drag-select copies without entering copy mode at all.

Mouse drag selections and selections started with `v`, Space, or `V` remain active during output and redraws, including when part of the selected range is outside the viewport. Copy reads the current text in that range, not a frozen snapshot. Resizing the pane or switching between its normal and alternate screens still clears the selection. Search results and double-click word selections retain their content-change checks.

## File viewer

Bind `keys.open_files` (unset by default), choose `open files` from the global menu, or choose `Browse files...` from a workspace menu to open an investigation tab.
The investigation opens beside the terminals, docked on the left at first; a workspace opening its first investigation starts from the placement last used. Drag the line between them to resize it. Right-click empty space in the tree to dock it elsewhere (`dock left` / `dock right` / `dock bottom`) or to show it full screen over the terminals (`show full screen` / `show split`). Each workspace remembers its own choice, dock and size. When the terminals would get fewer than 40 columns or the files fewer than 24 (8 and 6 rows when docked at the bottom), it shows full screen, and goes back beside the terminals once there is a little more room than that, so a window resized near the limit does not keep switching.
Click either side to give it the keys. `Esc` in the file list with nothing selected gives the keys back to the terminal and leaves the files shown.
`keys.open_files` gives the keys to an investigation shown beside a focused terminal, hides one that has them, and otherwise reopens the last investigation in that workspace. In full screen it switches between the investigation and the last terminal.
The investigation root stays fixed when a terminal changes directory; right-click empty space in the tree to change the root or create another investigation.
The top tab strip switches between terminals and investigations, and the second strip holds pinned files.
The list/results and document default to top/bottom; `toggle split direction` in the document's menu switches to left/right.
The right-click menu opens at the pointer and lists the actions for what was clicked: a file, a folder, empty space in the tree, the search fields and results, or the document. `F10` and the `[F10 actions]` button open the same menu at the selected row for the selection: the selected file or folder, or the document while it has the keys. Below, `F10` → an item means that item in the menu of the target it acts on.

| Key | Action |
| --- | --- |
| Up / Down, mouse click | Select and preview |
| Enter, double-click | Pin the file and focus its contents; expand a directory |
| Space | Focus the preview without pinning |
| Esc | Clear a document selection/search, then return to the list |
| Tab / Shift+Tab | Move between fields, results and contents |
| Ctrl+PageUp / Ctrl+PageDown | Switch pinned file tabs |
| Ctrl+W | Close the current file tab |
| Ctrl+P | Find files by fuzzy name/path |
| Ctrl+Shift+F | Search file contents |
| Ctrl+H | Open the replacement field |
| Ctrl+F | Find text inside the displayed document |
| Ctrl+E | Open the selected file in an external editor |
| Ctrl+C | Copy selected text in the document, or files in the list |
| Ctrl+X / Ctrl+V | Cut files / choose a paste destination |
| Shift+arrows / Shift+click | Select a range of files or text |
| Ctrl+click / Insert | Toggle an individual file or search match |
| F2 / Delete | Rename / confirm deletion to trash |
| F5 | Refresh the folder listings, the path index and the open document now |
| F10, right-click | Actions for the selection, or for what was clicked |

Content search updates after a short pause and combines a literal or regular expression with include/exclude globs.
Separate globs with commas; `**/*.rs` includes Rust files at the root and in subdirectories.
Case sensitivity, whole words and ignored files have separate controls.
Hidden files are included; `.git`, binary/non-UTF-8 files and symbolic links are excluded from content searches.
Searches cover at most 50,000 files and 10,000 matches, with a 15-second budget; narrow the conditions when results are limited.
Text previews support UTF-8 files up to 8 MiB and copy original text without line numbers.

Use Insert or Ctrl+click to exclude individual matches from replacement, or `F10` → `toggle matches in current file` for a whole file.
Enter in the replacement field opens a difference preview; Ctrl+Enter or its apply button writes the selected changes.
Regular-expression replacements support `$1` and `${name}` capture expansion; literal replacements preserve `$` literally.
A batch supports up to 1,000 files and 512 KiB of resulting text.
Files whose revision changed are skipped, and `undo last replacement` restores only files still at the revision written by that replacement.
Revision checks are optimistic: coordinate concurrent writers while applying replacements.

File copy/cut state stays within one server connection and is shown in the footer.
Paste and rename show the sources, destination and collision policy before execution; choose skip, another name, or confirmed replacement of files.
Directories are never merged or replaced.
Moves use atomic renames; a cross-volume move reports an error, so use copy and then explicitly delete the source when required.
Deletion uses the host trash service when available; permanent deletion requires its own confirmation.
Linux requires `gio` for trash, macOS uses Finder, and Windows uses the recycle bin.

Drop files or folders from your desktop onto the list to copy them into the selected folder, the folder of the selected file, or the root when nothing is selected.
Drops count only while the list has focus; a text field such as path search still receives the dropped paths as text.
A dialog shows the destination, the number of items and their size, and the names that already exist there: choose `upload` when nothing collides, otherwise `replace`, `keep both` or `cancel` (Left/Right and Enter, or click a button).
The folder is listed again afterwards and the first new item is selected.
The client sends the files and the server publishes them at once, whichever filesystem the tab browses (an SSH or container environment, or the server's own host, including a server on this machine): a failed or cancelled upload leaves nothing behind, `keep both` names copies `name (1).ext`, `replace` also replaces folders, and the progress card in the top-right corner cancels the upload until publishing starts.
`ui.upload_on_drop = false` turns drops off, and `ui.upload_max_bytes` and `ui.upload_max_entries` refuse larger uploads; see [Dropping files](/docs/persistence-remote/#dropping-files).

`F10` → `download…` saves the selected files and folders (several at once, folders recursively) on the machine running this client, not on the server's machine, and only on the machine of the client that asked. A dialog opens with the folder to save into: `~/Downloads` (the XDG download folder on Linux, the Downloads known folder on Windows), editable like any input; `~` and a path of this machine's own style are accepted. Selecting two items with the same last name, or names that differ only in case, is refused before anything starts. Everything is assembled in a hidden `.herdr-upload-*` folder inside the destination and published at once, so a failed or cancelled download leaves nothing behind; a name that already exists becomes `name (1).ext`. A symbolic link you select is followed and its target is saved, links inside a folder stay links, and FIFOs, sockets and devices are skipped. Entries that cannot be read, or whose names this machine cannot store, are skipped with a warning in the notice. A file that changes while it is read fails the whole download. The progress card in the top-right corner is shared with uploads (one transfer runs at a time) and cancels the download until saving starts. A download is refused above 16 GiB or 100,000 items; see [Downloading files](/docs/persistence-remote/#downloading-files).

The menus of a file and of the document hold `copy path` and `send path to terminal…`; a folder's menu holds `copy path`.
Path sending displays the destination pane and sends quoted text with no newline, while keeping the investigation open.
External editing uses `$EDITOR` (Unix default `vi`, Windows default `notepad.exe`), then returns to the investigation.
An investigation opened from a pane whose shell runs over SSH or inside a container browses that environment's filesystem instead of the Herdr server's, using the same tree, path search and preview, and `edit file` opens the editor there. It is bound to the environment (an SSH alias, or a container with its SSH host), not to a pane: requests go through a live pane of the same workspace running there, the focused one first. When none is left, the tab stays and shows `no pane running in <location>` until one returns. The `open_files` action reopens the tab matching the focused pane's environment, or opens a new one. A reopened tab moves its root to the pane's current directory when that is known and differs; the root does not follow the pane while the tab stays shown. The location prefixes the tab label and the path in the title: `app@devbox:work` and `files · app@devbox:/work` for a container behind an SSH host, `app:work` for a local container, `devbox:proj` for an SSH pane.
Content search, replacement and the file operations (copy, cut, paste, rename, create, trash and delete) keep their menu items and keys but only show `not available inside <location>` in such a tab; dropping files onto the list still uploads into that environment, and `download…` works in it too, reading through a live pane of the tab's environment. The preview and the listings of expanded folders refresh every 5 seconds instead of every second, one request at a time, and not while another request is running. Path sending and `copy path` use the path as the environment sees it, and sending only goes to the focused pane when it runs in the tab's own environment, host tabs included (`terminal destination is not in <location>` otherwise). Panes that were restored without a running shell count as host panes. Server versions without `pane.directory.*` keep listing the host's directory for such a pane and label it `host:`. Nested environments (an `ssh` or `docker exec` typed inside the pane) are not followed.
Roots, pinned files, positions, search conditions, orientation, and each workspace's split or full-screen choice with its dock and size restore from local client preferences; contents/results reload and clipboard/undo do not restore.
Moving the root: a `..` row tops the tree whenever the root has a parent. `Enter` or a double click on it raises the root one level and selects the folder you came from, like `Backspace`. `open as root` in a folder's menu makes that folder the new root, also inside an SSH or container tab. `change root` in the menu of empty tree space, or of the `..` row, takes a typed path. The `..` row is never sent, copied or operated on.

External changes refresh the current document, with updates held while text is selected. Every second (every 5 seconds in an SSH or container tab) the root and the shown expanded folders are listed again one after another, without collapsing or reloading the tree, and the path index is requested again, at most every 10 seconds (30 in an SSH or container tab), when a folder gains or loses entries. `F5`, `refresh files` in the menu of empty tree space, or the `[F5 refresh]` button starts that sweep immediately, including the index, and reads the open document now. Content search results are refreshed with `refresh content search` in the menu of the content search fields and results.

Override investigation-only shortcuts separately from terminal bindings:

```toml
[ui.file_workbench_keys]
next_file = "alt+right"
previous_file = "alt+left"
```

Servers that do not advertise `file.read` retain the legacy path picker, including Enter/Space path sending.

## Change anything

Every binding is configurable, including the prefix itself:

```toml
[keys]
prefix = "ctrl+a"
```

## Going prefix-free

You can bind Herdr actions to direct chords that need no prefix at all. The hard part is knowing which chords are safe, because terminals, shells, and desktop environments already own most of the keyboard.

Any chord works as a binding: `ctrl+j`, `alt+k`, whatever fits your hands. But a chord has to survive three layers before Herdr sees it: your operating system, your outer terminal (Ghostty, iTerm2, and others ship their own defaults), and the programs running inside the pane. `ctrl+j` reaches Herdr fine, but shells and editors treat it as enter. `alt+k` is free on Linux, but macOS composes it into a special character in most terminals. If you pick chords from these families, double-check them against your own terminal and OS shortcuts.

We mapped the default keybindings of Ghostty, iTerm2, Terminal.app, kitty, WezTerm, Alacritty, Warp, Windows Terminal, GNOME Terminal, and Konsole, plus the global shortcuts of GNOME and KDE. One modifier family is almost untouched everywhere: `ctrl+alt`. Terminals leave it free, it is not affected by the macOS option-key composing behavior that blocks plain `alt` chords, and it transmits even in terminals without a modern keyboard protocol. It is a safe default, but the choice is yours.

This setup keeps the prefix bindings working and adds direct chords on top:

```toml
[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]
```

A few `ctrl+alt` chords are taken elsewhere. Avoid these:

| Chord | Owned by |
| --- | --- |
| `ctrl+alt+arrows` | GNOME workspace switching, Ghostty and Konsole defaults |
| `ctrl+alt+t` | "Launch terminal" on Ubuntu and Fedora |
| `ctrl+alt+l` / `ctrl+alt+a` | KDE lock screen / attention window |
| `ctrl+alt+s` / `ctrl+alt+u` | Konsole |
| `ctrl+alt+f1..f12` | Linux virtual console switching |

If a direct chord does nothing, your terminal or desktop environment consumed it before Herdr could see it. Rebind either side: free the chord in the terminal's settings, or pick another chord in Herdr.
